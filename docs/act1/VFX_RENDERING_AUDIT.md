# Act I — VFX and rendering audit

**Static code audit; rendered screenshots not viewed in this step.**

## Existing pipeline

- `demonSlayerShader.ts`: toon/cel gradient, spectral and rim shading, inverted-hull outline techniques; `hadesSpriteBaker.ts` processes skinned models through an offscreen 3D renderer to 2D frames.
- `webglDemonSlayerVfx.ts`: original inked elemental ribbons, forked thunder, shockwaves, slash effects, glows. `visualCohesion.ts`: contact shadows, scars, Parashu ribbon and tip glint.
- `combatVfxClarity.ts` uses small/heavy/boss visual authority budgets. The gameplay code already has a substantial VFX vocabulary.
- Room backgrounds are stable *painted* images in the previous draft; MP4 switches during combat were explicitly disabled to prevent snap/decoder pressure.

## Risks and remedy (no blind spectacle changes)

| Layer | Source-level issue/opportunity | Evidence required |
|---|---|---|
| Body/weapon | Geometry may be painted/baked separately from trail | frame-level weapon tip + trail origin overlay |
| Primary arc | Existing parametric crescent follows estimated swing, not always skeletal tip | 4-direction attack screenshots + tip error in px |
| Elemental secondary | Multiple effects dispatch per ability | camera-view overlap fraction and contrast check |
| Contact/flash | Hit-stop and camera impulses assigned at many call sites | event timestamp vs visible contact |
| Enemy telegraphs | Tiered budgets but boss/player overlap not adaptively measured | readability when rage + boss + Astra active |
| Ground contact | Shadow calculation exists | paired frame comparison with airborne/grounded state |
| Environment | Multiple background sources and phase images | no rectangular clipping or undesired MP4 snap |
| Outlines | Ink hulls may scale poorly per model | screen-space width across zoom/scale |
| GPU/compositor | Caches, shaders and texture uploads are complex | actual frame captures + GPU/perf traces |

## Required visual style test

From the **gameplay camera**, each light attack should have a recognizable Parashu trajectory, not a screen-wide energy burst. A heavy needs stronger preparation and local contact. Agneyastra should read as fire/embers/heat, Vayavyastra as fluid/air, Vajrastra as angular branching energy. Boss shockwaves need obvious safe zones. Spectacle must stop short of hiding the player hitbox or an enemy's active telegraph.

## Acceptance thresholds (to measure)

No hard-cropped square, no invisible actor, no full-screen whiteout from ordinary light attack, high-contrast enemy telegraph readable during player's strongest Astra, no mid-fight MP4 swap, consistent foot-shadow anchoring and no major colored contour spilling outside the pose.
